# :fontawesome-solid-dungeon: Altar

The **Altar** is LychD's browser interface. Ask a question in Bridge. When a reply arrives,
its Run ID lets you follow that same attempt into Orb to see what was recorded and into Loom
to read the workflow it was meant to follow. Atlas keeps the larger project in view across
conversations.

## Bring one Intent

For a first look from a checkout, [trace a sample Run](../../onboarding/explore/one-run.md).
The developer preview gives you a conversation, a workflow score, and evidence to inspect.

For a first turn on your own model host, follow [Summoning](../../summoning.md). Before startup,
agree how to [close the trial](../../summoning.md#close-the-rite). The public stop command refuses
an active Vessel. [The Awakening](../../summoning.md#the-awakening) takes you through loopback
access, the local credential and the four observations that establish a first reply. Keep the
listener on literal loopback in a dedicated same-host browser profile. The credential proves local
possession and confers full local authority. A remote road requires its own [access
profile and qualification](../../deployments/index.md).

The installed Altar opens at `http://127.0.0.1:7134/` in **Orb**. Open **Bridge** in the
left rail, choose **New Séance**, and offer a bounded Intent. If it pauses for your consent,
the request appears beside the turn that needs your judgment.

## Carry the Run with you

A séance can hold many turns. Each admitted turn opens one [Circle](circle.md), the Invocation
in which the casting performs its exact Scroll. Carry that turn's **Run ID** from Bridge into
the other instruments to find evidence about the same attempt.

| What you need to establish | Instrument |
| --- | --- |
| What was offered, what judgment is pending, and what settled? | [Bridge](./bridge.md) |
| What did this conversation contain, and which words should we carry into later work? | [Séances](./seances.md) within Bridge |
| What can we draw, develop, organize and return to across conversations? | [Atlas](./atlas.md), including [Canvas](../../compositions/canvas/index.md) authoring |
| Which quotations are working material, and which public notes have entered Archive? | [Memory](./memory.md), opened from Bridge or Séances |
| Which stations and paths does this exact Scroll permit? | [Loom](./loom.md) |
| How can I judge one retained answer against explicit criteria? | [Loom manual output review](./loom.md#review-a-retained-output) |
| What was observed about readiness or a physical transition? | [Nexus](./nexus.md) |
| What can this installation advertise, and whose access can I inspect? | [Nexus operations](./nexus.md#choose-an-operation) |
| Which colleagues welcome work requests? | [Nexus colleague presence](./nexus.md#see-which-colleagues-welcome-requests) |
| Which Runs are before us, what evidence is arriving, and where does capture run out? | [Orb](./orb.md) |

On the left rail, **Applications** opens the [dashboard](applications.md). Its chevron or
context menu opens the quick list. **Scavenger** is
visible even when Scavenger is unconfigured. To submit a market observation the host needs the
[finite feed observation profile](../../compositions/scavenger/market.md#finite-feed-observation).
In **Atlas**, LychD's own Canvas stays pinned first. A project can begin there before it has
a conversation or a Run.

For one turn, open the reply menu and choose **View run in Orb**. From its evidence you can
open the exact score in Loom or follow a recorded physical transition into Nexus. To compare
several Runs, use the [parallel field](orb.md#read-the-parallel-field). In Nexus, **Preview**
only inspects a plan. **Request transition** sends a real maximum-priority request to change
the machine.

## Return to Bridge

Choose **Bridge** on the left rail to return to the last explicitly selected conversation in this
browser document. **Browse séances** opens the catalogue. The dock's **Open Séance** opens the
current conversation for inspection, and **Continue in Bridge** explicitly selects an inspected
conversation for live exchange.

## Keep Bridge beside the work

Use the named **Bridge** control at the work area's edge to open or collapse the panel. New layouts start
on the left at a compact width; valid saved side and width preferences remain in use. Drag its divider to
change its width, or focus the divider and use its arrow keys. The **⇄** control chooses the
other side. A wide window makes room beside the panel; a narrow window opens it as a
modal sheet with Escape and a return to the opener. Layout preferences may be remembered in this
browser; conversation drafts and unresolved requests retain their existing open-document boundary.

Switching instruments keeps the selected conversation. Collapsing Bridge does not cancel its
Run, submit a draft or approve a request. The context label identifies the work you are viewing;
it does not transmit the work to a model. Exact Bridge session, Run and consent links remain
valid, including links from Orb. Investigation and public-note focus stay distinct from the
ordinary conversation. Read [Bridge](bridge.md) for those operations and recovery boundaries.

## The surface and its owners

Execution belongs to the [Vessel](../../sepulcher/vessel/index.md), committed truth to the
[Phylactery](../../sepulcher/phylactery/index.md), and physical readiness to the Orchestrator.
The Altar projects those accounts so the Magus can inspect and act through their admitted seams.

The delivered interface is English-only and uses **LychD Dark**. **Appearance** on the left rail
offers **Violet**, **Iris**, and **Neutral** decorative accents, plus **Reset to LychD Dark**.
The choice is local to this browser and falls back to the default if its saved value is invalid
or storage is unavailable. Focus, activity, warning and refusal keep their established colours;
the selection changes neither retained content nor authored Canvas ink. It is an accent preference,
not a light/system selector or a free-form theme editor. Future
[locale](../../adr/15-frontend.md#interface-locale-and-content-language) and wider
[palette](../../adr/15-frontend.md#canonical-appearance-and-bounded-palette-configuration)
contracts remain with Frontend.

## Presentation direction

Start with one of the proposed screens. In [Bridge](bridge.md#the-bridge-workspace), follow a
turn or open a file beside the conversation. In [Applications](applications.md), browse the
catalogue and pin a shortcut. In [Loom](loom.md), inspect a node or trace a permitted branch.
The [software-change example](loom-sdlc.md) follows an Intent through the blueprint and into a
separate evaluation workflow. [Moving between screens](workspace-design.md) explains which
tools travel with you. The [Nexus design](nexus-design.md) covers operations, users and access policy.

The graphite frame leaves black spatial surfaces to the work. Neutral primary actions, a quiet
purple instrument identity, cyan manipulation controls, and green observed activity have distinct
roles. Bridge gives the conversation room on its route and offers a compact composer beside
other work. Séances gives retained conversations room for reading. Atlas opens the project
catalogue and Canvas drawing boards. Loom reads as a declared score, Nexus as a readiness
inspection board, and Orb as an evidence field. The future
[Atlas memory map](atlas.md#the-shared-memory-map) describes how the instruments can refer to the
same retained knowledge.
Canvas's **Selection tools** unfold when ink or nodes are selected, or can be opened directly.
Identity and history unfold as needed, while uncertainty,
consent, capture limits, and physical consequences stay beside the choices they qualify.
[Frontend's reading hierarchy](../../adr/15-frontend.md#reading-hierarchy-and-visual-direction)
owns this shared design.

Follow [Atlas's concerns and citations](atlas.md#reading-direction),
[Bridge's conversation and recovery](bridge.md#the-bridge-workspace),
[Orb's parallel evidence field](orb.md#reading-direction), [Nexus's preview and observations](nexus.md#reading-direction),
or [Loom's declared score](loom.md#reading-direction). Current controls and the boundaries of
graph expansion remain those described in the operating sections and [State of
Work](../../state-of-the-work.md#altar-and-observability).

Artwork supports the entrance rather than repeating behind work on every instrument. The existing
empty-Bridge scene has a retained [asset notice](https://github.com/hexanomicon/lychd/blob/main/clients/web/src/lib/assets/altar/NOTICE.txt)
and [generation prompt](https://github.com/hexanomicon/lychd/blob/main/clients/web/src/lib/assets/altar/working-altar.prompt.md).
They distinguish the generated Altar scene, the authorized character reference, and their terms.
The source distribution retains [third-party notices](https://github.com/hexanomicon/lychd/blob/main/THIRD_PARTY_NOTICES.md);
their custody does not require a permanent footer competing with the work.

### Shared workflow station inspector

The proposed inspector gives Loom and Orb the same panel when you select a workflow station.
The panel identifies the station and its exact Pattern revision. Each instrument opens the view
that answers the question you came with.

- **Loom opens Definition.** Read the station's purpose, permitted successors, declared input and
  output schemas, and any supplied prompt template. A placeholder such as `{{evidence}}` names a
  declared input binding in the template.
- **Orb opens Attempt.** Read the selected Run and station attempt, with its recorded phase,
  events, and any inputs or results available to inspect. **Definition** opens the station from
  the exact revision used by that Run when it can be verified. The panel shows capture gaps and
  distinguishes an unavailable value from a recorded empty value.

For example, an Explorator's definition could specify an **Evidence Packet** as its output. Select
it in Loom to see what the packet should contain and where it can go next. Select an observed
Explorator attempt in Orb to see its recorded outcome. Open **Definition** beside it to check
the expected output without leaving the Run.

The current [Loom station inspector](loom.md#read-identity-then-possibility) and
[Orb evidence inspector](orb.md#locate-the-event) already provide the starting views. Orb's live
feed carries structural records and metadata. Showing prompt or output bodies would require a
separate authorized read.
