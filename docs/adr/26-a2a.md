# :material-access-point-network: 26. Necropolis: The Intercom Bridge

!!! abstract "Context and Problem Statement"
    High-order intelligence is physically bound by the finite constraints of single-node hardware. The machine requires a mechanism to trade labor and share context with other sovereign nodes without surrendering local authority or deterministic resource control. The challenge lies in establishing a decentralized architecture that supports the "Long Sleep" — the ability for thoughts to span network boundaries and survive high-latency rituals.

## Requirements

- **RFC 8615 Discovery:** Mandatory implementation of the `/.well-known/` path prefix to facilitate autonomous peer discovery.
- **Identity Transparency:** Adoption of the `agent-card.json` standard (A2A v0.3.0) to exchange public Sigils and cognitive capabilities.
- **Asynchronous Handshake:** Support for the "Long Sleep"—suspending a reasoning ritual and returning a `202 Accepted` status while high-latency labor is performed by a peer.
- **Native Substrate Alignment:** Mandatory integration with the system's native **[Vessel (11)](11-backend.md)**, **[Phylactery (06)](06-persistence.md)**, and **[Ghouls (14)](14-workers.md)**.
- **Type-Safe Sovereignty:** Reliance on native Python type hints and Pydantic models as the definitive contract for all cognitive labor.
- **Resource Lease Enforcement:** Mandatory integration with the physical arbiter to ensure incoming swarm requests are subject to revocable hardware leases.
- **Context Preservation:** Utilization of a unified `context_id` to ensure multi-turn negotiations maintain a coherent reasoning history across the Legion.

## Considered Options

!!! failure "Option 1: Model Context Protocol (MCP)"
    Utilizing the MCP standard to connect models to data.
    - **Cons:** **Functional Reduction.** MCP is designed for connecting "Models to Tools." It treats capabilities as stateless functions. In LychD, **Agents are not Tools**; they are stateful, autonomous entities that require multi-turn negotiation and asynchronous handshakes, which MCP cannot sustain.

!!! failure "Option 2: FastA2A / UTCP (Middleware Tax)"
    Utilizing the FastA2A library or a separate Universal Tool Calling Protocol.
    - **Cons:** **Architectural Bloat.** FastA2A brings its own Starlette-based server and volatile memory broker. This creates "Grafted Tissue" that duplicates the **Vessel's** Litestar logic and the **Ghouls'** SAQ queue. UTCP introduces a "Translation Tax," converting Pydantic models into intermediate JSON schemas, increasing entropy and hallucination risk.

!!! success "Option 3: Native Litestar Intercom (A2A Specification)"
    Implementing the A2A v0.3.0 specification as a native Extension using the existing Litestar and SAQ substrate.
    - **Pros:**
        - **Zero-Dependency Purity:** Leverages the **Vessel's** existing high-performance router and the **Phylactery's** persistent task queue.
        - **Pydantic Sovereignty:** The tool definitions scried in the **[Dispatcher (22)](22-dispatcher.md)** are sent directly over the wire without translation.
        - **Long Sleep Support:** Natively uses Pydantic AI's `call_deferred` to hibernate threads while remote nodes labor.

## Decision Outcome

The **A2A Intercom** is adopted as the native network of the machine. It is implemented as a native component of the **Vessel** — not a separate extension — grafting A2A v0.3.0 communication patterns directly onto the Litestar application.

!!! note "Intents, Not Tensors"
    The A2A Intercom exchanges **structured Pydantic intent objects**, not raw model weights or tensor streams. The network is a high-level diplomatic layer; all heavy compute happens locally on the receiving node's own iron. This is what makes the protocol viable over commodity internet connections.

### 1. The Intercom Router (The Bridge)

The extension registers a dedicated Litestar Router mounted at `/a2a`. It handles the core JSON-RPC methods defined by the A2A specification:

- **`message/send` (The Ingress):** Accepts a cognitive intent as a structured Pydantic object. Validates the schema, checks the sender's Sigil against the **[Ward (38)](38-iam.md)** and grants appropriate authority, enqueues a **Ghoul (14)** in the `queue` chamber, and returns `202 Accepted` with a **Task ID**.
- **`tasks/get`:** Allows peers to poll for the status of a long-running ritual.
- **The Callback (The Egress):** Once the local Ghoul completes the work, the Intercom uses `httpx` to deliver the resulting **Artifact** (a structured Pydantic response, not raw tensors) to the peer's registered callback URI. This unblocks the peer's Stasis Protocol and allows their frozen Agent to rehydrate.

!!! note "Task Status and Observation"
    A2A task state uses the same split as local Graph runs: the task record and callback artifact are recovery and result truth; optional event streams, polling views, and traces are observation truth. Peer-facing statuses must distinguish completed work from blocked, failed, expired, or revoked leases so a remote graph does not confuse transport silence with a negative answer.

!!! note "Hook Correction: FastA2A Mounting"
    The deprecated `Agent.to_a2a()` convenience (removed in pydantic-ai 2.0) is not the binding. The current hook is `fasta2a.pydantic_ai.agent_to_a2a(agent)`, which returns a Starlette ASGI application mounted under **[the Veil (40)](40-proxy.md)** alongside the native router. FastA2A itself supplies the Storage, Broker, and Worker abstractions and the JSON-RPC state machine, so that machine is not hand-rolled; the correct posture is to bind FastA2A's Storage and Broker to the native **[Phylactery (06)](06-persistence.md)** and **[Ghoul (14)](14-workers.md)** SAQ substrate rather than accept its default volatile broker. The Litestar-native mounting of the `/a2a` router and the `/.well-known/` discovery path remains valid and continues to own routing, the **[Ward (38)](38-iam.md)**, and Sigil authority.

### 2. Sovereign Discovery (RFC 8615)

To facilitate peerage within the **[Legion (42)](42-legion.md)**, the node serves its identity via the standard "Well-Known" URI:

- **`/.well-known/agent-card.json` (The Passport):**
    - **Identity:** Public Sigil and active Personas.
    - **Skills:** A manifest of agents and their Pydantic schemas, sourced from the **Dispatcher's** registry.
    - **Economics:** The Tithe requirements for labor, as defined in **[Economics (41)](41-x402.md)**.

### 3. The Pydantic Covenant

The Intercom rejects all mundane middleware (UTCP).

- **Type-to-Type:** Communication between Liches is a direct exchange of Pydantic models.
- **Stasis Handshake:** When the **Dispatcher** resolves an intent to a remote peer, it triggers a `call_deferred` event. The Intercom serializes the intent, signs it with the local Sigil, and manages the network transport.

### 4. The Warden's Lease

Every incoming swarm task is treated as unprivileged labor.

- **Resource Lease:** The **[Orchestrator (23)](23-orchestrator.md)** grants a temporary hardware lease to the swarm task.
- **Preemption:** If the local Magus initiates a reflex (e.g., Voice), the Orchestrator revokes the lease. The swarm-ghoul is paused, its state is persisted to the Phylactery, and the GPU is reclaimed.

### 5. Extension Freedom

While A2A provides the standard for agentic communion, the architecture remains open. Extensions are free to mount raw Litestar routes or alternative protocols (e.g., WebSockets for streaming) as needed. The Intercom serves as the high-level diplomatic layer for both the **[Legion](42-legion.md)** and the broader Necropolis.

Under the **MPL 2.0 License**, the Magus is free to create **private extensions**. Because MPL allows linking with separate proprietary files without converting the entire Larger Work, proprietary "Secret Sauce" capabilities can be grafted into a local Lich without being forced open. This preserves the A2A network by ensuring individuals can still participate in the Swarm while maintaining sovereign, private advantage locally.

### 6. The Necropolis (Sovereign Peerage)

The Necropolis is the name for the broader network that emerges when sovereign Liches — each with their own Phylactery, their own identity, their own **[Legion](42-legion.md)** of Thralls — meet as peers.

The primary unit on this network is the sovereign individual node, not the company. In this model, a company is an emergent coordination graph built from many such nodes: a policy-composed membrane of people, scopes, and exposed capabilities rather than a soul-bearing actor that owns the underlying Phylacteries.

This is the post-SaaS inversion. The human does not disappear into a vendor surface; instead, the sovereign Lich negotiates with company APIs, peer nodes, and public services on the human's behalf while the durable memory and identity substrate remains local.

Within the **[Legion](42-legion.md)**, Thralls obey via direct Vessel HTTP — no negotiation required. On the Necropolis, the A2A Intercom carries **negotiations** between strangers, settled via **[The Toll (41)](41-x402.md)** and gated by **[The Veil (40)](40-proxy.md)**.

For cross-implementation doctrine, the architecture recognizes independent implementations:

- **Implementation:** A sovereign daemon implementation with its own internals and evolution path. An implementation that speaks the A2A Intercom can enter the Necropolis and negotiate labor.

The Necropolis requires no shared body. A2A presence makes a foreign implementation visible and negotiable without requiring compatibility with LychD internals, configuration doctrine, layout expectations, or security covenants.

- **Internal Graph vs Public Surface:** A sovereign Lich may maintain a rich private agent graph, internal skills, and private priors while advertising only selected labor over A2A. Necropolis presence exposes chosen interfaces, not the whole soul.
- **Labor, Not Assimilation:** A2A is the exchange of bounded labor between sovereign nodes. It does not imply surrendering the deeper grooves of a Phylactery, the internal structure of a private graph, or the right to decide which patterns remain rented and which are later internalized through Assimilation.
- **Workload Pools:** Nodes publish capability requests to shared channels. Idle peers subscribe based on their **[Orchestrator (23)](23-orchestrator.md)** status and bid based on their configured compute cost.
- **The Revocable Lease:** When a peer accepts a Necropolis task, it grants a temporary hardware lease. If the peer's local Magus speaks, the lease is revoked — the foreign task is paused, serialized, and hibernated until the GPU is free.
- **The Dumb Portal Anti-Pattern:** A sovereign node on the Necropolis cannot be treated as a "dumb portal." The network exchanges Intents, not OS commands. A node sends an Intent; the receiving sovereign configures its own Covens to fulfill it on its own terms.

The Necropolis is the destination that every organ in the Sepulcher was built to reach. The **[Legion (42)](42-legion.md)** proves the pattern works within the Magus's domain. The Necropolis extends it to the world.

The Legion extends one Magus across owned iron. The Necropolis lets sovereign nodes meet without surrender.

### 7. The Nostr Relay (The Shadow Bus)

While HTTP is the primary bridge for high-performance direct communication, the Intercom supports **Nostr** as an asynchronous, censorship-resistant transport layer. 

- **NAT Traversal:** By subscribing to shared relays, Liches can exchange A2A messages without either node needing a public IP or open ports.
- **Decentralized Discovery:** Skills are published as job capabilities, allowing the machine to discover and be discovered by the broader autonomous network.
- **Encrypted Intent:** All Nostr-based A2A traffic is strictly encrypted, ensuring that only the intended recipient can decode the cognitive intent.
- **Trust the Key, Not the Relay:** A relay is a dumb, swappable bus. It can drop or censor an event, but it cannot forge one: identity is the node's key, and every event is signed and verified at the edge. If a relay censors or dies, the Lich resubscribes elsewhere with no change to identity — the same property that lets a seed node be replaceable while the repository identity is not. An untrusted relay may carry the pointer; only a valid signature makes it real.

*Viva la resistance.*

## Consequences

!!! success "Positive"
    - **Substrate Integration:** Utilizing SAQ and Postgres ensures that swarm tasks are as resilient and persistent as local tasks.
    - **Latency Optimization:** Bypassing intermediate protocols (UTCP) eliminates the serialization overhead for complex data structures.
    - **Sovereign Security:** The Intercom is a standard router, meaning it is automatically protected by the **[Proxy (40)](40-proxy.md)** and gated by the **[Ward (38)](38-iam.md)**.

!!! failure "Negative"
    - **Integration Burden:** FastA2A supplies the A2A JSON-RPC state machine along with its Storage, Broker, and Worker abstractions, so the machine is no longer hand-rolled. The remaining burden is mounting its ASGI app under the Veil and rebinding its Storage and Broker onto the native Phylactery and SAQ substrate so swarm tasks inherit the same persistence and lease discipline as local labor.
    - **Protocol Sensitivity:** The node is strictly bound to the A2A versioning; breaking changes in the specification require synchronized updates across the Federation.
